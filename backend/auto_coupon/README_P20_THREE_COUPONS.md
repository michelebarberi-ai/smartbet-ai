# Build 45 / P20: three coordinated automatic coupons (NOT deployed)

- Phone settings now offer 3–15 fixtures; manual Schedina AI and the original
  on-device coupon settings remain unchanged.
- The new daily preference `systemMode: THREE_SAME_FIXTURES` explicitly
  requires exactly 3 coupons with identical fixture IDs, order and kickoff.
  Each coupon is distinct by at least one actual market, and every market has
  a real official-engine prediction and quoted odd above threshold.
- `SINGLE` or missing `systemMode` retains prior server behavior.
- Official Flutter headless worker chooses real selections already produced
  by the Value/Balanced/Premium engine profiles. A candidate market is never
  guessed or generated by Node. **Not every day can produce 3 variations.**
  Until the official engine offers more independent alternative markets per
  fixture, triple mode may often return `no_eligible_coupon`.
- The saved JSON is `{events:[...],coupons:[{name,events},...]}`. `events`
  mirrors the primary coupon for older readers, and the phone displays the
  complete set when present. All three variants are verified before saving.
- NO scheduled worker, push credentials or Render deployment is enabled here.
  Hosting of the official Flutter runner, scheduling and real device tests
  are separate steps. The runner can take more time for 15 fixtures.
